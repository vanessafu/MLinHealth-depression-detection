# Stage 1 dev benchmark：扩充 Ellie 问题库 + 换 embedding

任务 5060746（a40，2026-11-24，用时 1 h 53 min）。dev 共 56 个 session，标签均值 6.59。
打分模型为 Qwen3-4B-Instruct-2507，评估脚本是 `scripts/evaluation/stage1_bench.py`，中间数据只存在 `$TMPDIR` 里。

## 1. 问题库扩充

- 挖掘来源：train 里的 Ellie 句子，取自修复后转写的原始 ASR 文本。
- 挖掘方法：先做模糊聚类（相似度 ≥ 85），只保留在 ≥ 3 个 session 里出现过的簇。如果一个簇在官方受访者转写中也常见，或者只是语气词，就去掉。
- 新问题库：旧库 70 条 + 新增 143 条，共 213 条，存为 `resources/ellie_questions_mined.csv`。
  - 新增的 143 条：main 71、followup 34、backchannel 29、opening 8、closing 1。
  - 例如 "do you consider yourself shy or outgoing" 现在已经在库里了。
- 用新问题库重新判定说话人：共改了 2388 个片段的标签。
- 问答对数量：

| | 每个 session 的问答对（中位数 / 均值） | 问答对 ≤ 3 的 session 数 |
|---|---|---|
| 旧问题库 | 17 / 15.3 | 24 |
| 新问题库 | **20 / 18.8** | **16** |

## 2. 候选相关性（LLM 判定）

做法：对 dev 的每个 PHQ 题，取检索出的前 6 个候选，让 Qwen3-4B 回答 yes/no，判断这个候选是否和该题相关。

| 配置 | precision@1 | precision@6 | 前 6 个里至少有 1 个相关 |
|---|---|---|---|
| 旧问题库 + bge-large | 0.114 | 0.064 | 0.307 |
| 新问题库 + bge-large | 0.173 | 0.079 | 0.370 |
| 新问题库 + Qwen3-Embedding-0.6B | **0.175** | **0.082** | **0.375** |

- 新问题库的提升比较明显：precision@1 从 0.11 升到 0.17。换 embedding 模型只带来很小的额外提升。
- 来自 question map 的命中，precision 是 0.128；纯 embedding 检索的命中只有 0.047–0.067。也就是说，固定问题映射比语义检索可靠。
- **相关性的绝对值都很低。** 对超过 60% 的题，前 6 个候选里一个相关的都没有。各题的 precision：
  - item1（兴趣）和 item4（疲劳）稍好，在 0.10–0.15 左右；
  - item5（食欲）、item7（注意力）、item8（动作）只有 0.03–0.06。
  - 原因是访谈本身很少直接问到这几题，所以检索不到真正相关的内容。
- Qwen3-Embedding 在 item5 上几乎从不超过证据阈值，有证据的比例只有 1.8%，bge 是 36%。它的相似度分布和 bge 不同，−1 / 阈值需要单独校准。

## 3. dev 结果

### 零样本

| 配置 | CCC | RMSE | MAE | AUROC（PHQ≥10） | 平均预测分 |
|---|---|---|---|---|---|
| 旧问题库 + bge | 0.194 | 9.99 | 8.66 | 0.704 | 14.6 |
| 新问题库 + bge | 0.265 | 9.45 | 8.36 | **0.823** | 14.3 |
| 新问题库 + Qwen3-Emb | **0.282** | **8.85** | **7.62** | 0.774 | 13.5 |
| 新问题库，不检索，全部问答对 | 0.103 | 14.11 | 13.08 | 0.761 | 19.5 |

- 零样本的主要问题是**系统性高估**：平均预测 13–15 分，真实均值只有 6.6。0–4 分档的 MAE 在 10 分左右。
- 把全部问答对都放进提示词时，高估最严重，平均预测达到 19.5。模型在无关内容里也会找到"症状"。所以检索这一步是必要的。

### LoRA

训练数据：train 163 个 session，其中 130 个用于训练，33 个做早停验证。评估在 dev 上。

| 配置 | CCC | RMSE | MAE | AUROC | 15–19 分档 MAE | 20–24 分档 MAE |
|---|---|---|---|---|---|---|
| 旧问题库 + bge（基线） | 0.442 | 5.47 | 3.96 | 0.680 | 8.33 | 7.57 |
| **新问题库 + Qwen3-Emb** | **0.543** | **5.10** | **3.64** | **0.711** | 7.43 | **1.79** |

- 新配置是按相关性判定的结果选出来的，选的时候没有看 dev 标签。LoRA 后 CCC 提升 0.10，各题的 QWK 也几乎都提升了。
  - 提升较大的题：item6 从 0.35 到 0.50，item7 从 0.24 到 0.35，item5 从 0.28 到 0.37。
- LoRA 解决了高估问题，平均预测为 6.4，真实均值 6.6。但模型现在**往中间收缩**：
  - 15–19 分档仍然低估约 7–8 分；
  - 二分类 F1 只有 0.44，15 个阳性里大多数没有被识别出来。

## 4. 结论与下一步

1. **新问题库值得采用**：问答对更多，候选更相关，零样本和 LoRA 都有提升。Qwen3-Embedding 只比 bge 好一点，可以作为默认，但要重新校准 item5 的阈值。
2. 现在的主要瓶颈在检索：前 6 个候选的相关率只有 8%。建议：
   - 扩充 question map，这部分的命中比 embedding 准一倍；
   - 用 cross-encoder 或 LLM 对候选做重排；
   - 允许某题在"没有证据"时输出一个先验值。
3. LoRA 后高分段收缩，可以考虑：对高分样本加权、用分档损失，或者在 train 上做交叉验证，再做线性后校准。
4. 注意：dev 只有 56 个样本，CCC 的置信区间大约是 ±0.15。这次的提升方向是一致的，但幅度需要多折实验或 test 集来确认。

## 6. 分析

### 6.1 Stage 2 没有带来提升

- 在 train 的 OOF 上，融合把 CCC 从 0.729 提到 0.769，所以 β 选到了网格最大值 1.0，也就是完全采用音频修正后的分数。
- 但在 dev 上，CCC 从 0.536 降到 0.526，MAE 从 3.50 升到 3.78。音频修正只在最高分段有帮助：20–24 分段的 MAE 从 4.7 降到 2.5，其余分段都变差。
- 我认为原因是 **train 上的 OOF 是偏乐观的**。每一折的验证集既用来做早停（选 val CCC 最高的 epoch），又用来算 OOF 分数，等于在同一份数据上挑了一次最好的结果。β 是在这份偏乐观的 OOF 上选的，所以被推到了 1.0。
- 另外，25 个模型的 best_epoch 差别很大，从 0 到 196 都有。其中有几折在第 0 个 epoch 就停了，说明这些折的音频模型基本没学到东西。
- 辅助任务的结果：疲劳三分类 QWK 0.39；动作二分类 AUROC 0.54，接近随机。
- 改进方向：
  1. 早停改用 train 内部再划出来的验证集，或者固定 epoch 数，让 OOF 不再偏乐观；
  2. β 网格加上 0 附近更细的取值，或者用嵌套交叉验证来选 β；
  3. 动作这一项的正样本太少，可以考虑把 w_mov 设为 0。

### 6.2 不做 embedding 筛选反而略好

- B（全部 Q-A 对）CCC 0.574，第一部分的检索单模型是 0.543。两者用的是同一个 80/20 划分。
- B 最明显的提升在 item1（兴趣）：QWK 从 0.09–0.20 升到 0.42。第一部分发现检索的相关率只有 8%，LoRA 之后模型自己能从完整的上下文里找到证据，检索反而会把有用的信息筛掉。
- 代价：
  - 训练时间约 112 分钟，是检索版的 2–3 倍；
  - 高分段低估更严重，15–19 分段的 MAE 达到 8.99。
- 零样本时情况正好相反：第一部分里全部 Q-A 对零样本的 CCC 只有 0.10。也就是说，"全部上下文"只有在经过微调后才有用。

### 6.3 官方转写和我们的 ASR 管线基本持平

- C（官方转写，不经过音频）CCC 0.570，和 B 的 0.574 几乎一样。C 的逐题 QWK 最均衡，PHQ≥10 的 F1 最高（0.48）。
- 由此得到的结论：
  - 我们的 ASR + 说话人判定 + Q-A 配对，**没有比官方转写损失明显的信息**。转写质量目前不是瓶颈。
  - 官方转写虽然没有说话人标签，但 LoRA 依然能学好。所以 Q-A 结构本身也不是必需的。
- 官方转写在零样本时严重高估：平均预测 19.5 分，CCC 0.09。没有说话人标签时，模型会把采访者的问题也当成受访者的症状。

### 6.4 总体判断

- dev 只有 56 个样本，CCC 的置信区间大约是 ±0.15。**0.526–0.574 之间的差异都不显著**，五个 Stage 1 单折模型在 dev 上本身就分布在 0.48–0.55 之间。
- 比较可靠的结论有三条：
  1. LoRA 是最主要的提升来源：CCC 从 0.1–0.3 升到 0.53–0.57，对所有输入形式都一样。
  2. 当前设置下 Stage 2 音频没有帮助，需要先修正 OOF 的选择偏差，再重新评估。
  3. 检索和 Q-A 配对在微调之后的收益很有限，长上下文（全部 Q-A 对或整份转写）至少同样好。
- 所有配置都在 15–19 分段严重低估（MAE 7–9 分），PHQ≥10 的召回率低。这是下一步最该解决的问题，可以试高分样本加权或按分段加权的损失。
- 下一步建议：
  1. 对 B 和 C 做五折 OOF + 多 seed 集成，用 bootstrap 估计 dev 上 CCC 的置信区间，确认差异是否真实存在；
  2. 修正 Stage 2 的早停方式和 β 选择后重跑 A；
  3. 如果 test 集标签可用，最后只在 test 上评估一次。
